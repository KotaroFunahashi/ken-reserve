## TDDベースの実装タスク(PR構成)

### 1. 基盤：CI/CD と Testcontainers の導入

* **PR #1: MySQLコンテナによるテスト基盤構築**
* テスト: 空のテストクラスで MySQL コンテナが起動し、接続できることを確認。
* 実装: `build.gradle.kts` に Testcontainers (MySQL) の依存関係を追加。
* 実装: GitHub Actions で Docker が動く CI パイプラインを構築

### 2. 基盤：認証とユーザー管理

* **PR #2: ユーザー認証機能 (Auth)**
* テスト: `UserRepositoryTest` でユーザーの保存・検索をテスト。
* テスト: `SecurityConfig` のテストで、未認証ユーザーが `/` にアクセスできないことを確認。
* 実装: エンティティ、リポジトリ、`SecurityConfig` の実装

### 3. ドメイン：予約システムの骨格

* **PR #3: 予約エンティティとバリデーション**
* テスト: `ReservationRepository` で重複する時間帯の予約が保存できない制約をテスト。
* 実装: `Reservation` エンティティとリポジトリの実装

### 4. ロジック：カレンダー生成（TDDの難所）

* **PR #4: 週間カレンダーのスロット判定**
* テスト: `ReservationServiceTest` で、特定の日時のスロットが「予約済み」「空き」「バッファによるブロック」になるかを、モックを使って網羅的にテスト
* 実装: カレンダー表示用の DTO と、判定ロジックの実装

### 5. ロジック：予約の制約（バッファルール）

* **PR #5: 前後30分ブロックのビジネスルール**
* テスト: 新規予約を申請した際、既存予約の前後30分以内であれば例外を投げるテスト
* 実装: `ReservationService` へのバッファルール組み込み

### 6. UI：共通デザインとユーザー管理画面

* **PR #6: レイアウトとユーザー管理 (CRUD)**
* テスト: `UserControllerTest` (MockMvc) で、一覧表示と登録フォームのバリデーションをテスト
* 実装: Tailwind CSS 導入、共通レイアウト、ユーザー管理画面一式

### 7. UI：メイン機能（カレンダーと申請）

* **PR #7: ホーム画面と予約申請フロー**
* テスト: `HomeControllerTest` で、カレンダーのスロットをクリックして予約申請が飛ぶまでの挙動をテスト。
* 実装: `index.html` と予約申請 API の実装

### 8. UI：ステータス管理

* **PR #8: 承認・却下・通知確認**
* テスト: 講師が承認ボタンを押すとステータスが `APPROVED` に変わることをテスト。
* 実装: 承認/却下、生徒への通知確認ロジックと画面

### 9. 仕上げ：予約の直接管理

* **PR #9: 予約一覧と手動メンテナンス**
* テスト: `ReservationControllerTest` で、過去の予約削除不可チェックなどをテスト
* 実装: 予約一覧画面、講師による直接登録・削除機能
